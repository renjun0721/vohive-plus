# VoHive Plus 0.1.8-personal-classic

按用户选择增加可选 QMI 漫游白名单，以完整 0.1.7 个人版为基线；本轮没有新增上游移植。配置文档见 [ROAMING-OPERATORS.md](../../source/vohive-plus/ROAMING-OPERATORS.md)。

## 行为

- 按实时 ICCID 绑定允许的运营商顺序，当前用户配置联通 LTE 46001 优先、移动 LTE 46000 备用。真实 ICCID 不在公开仓库。
- 启动/Worker 重建后，即便模组已自动注册其他网络，也请求首选网络；普通 QMI 驻网恢复不会重新开启自动选择。
- 每项等待 90 秒；请求直接失败则等待 20 秒再尝试下一项；全部失败后等待 5 分钟，从首选重试，绝不因失败回退到自动选网或白名单外网络。
- 稳定驻留移动时保持连接，避免定时断网干扰收信；掉网持续 30 秒或服务/设备重建后重新优先尝试联通。
- 操作前核对 Worker、缓存和实时卡身份；扫描、卡未就绪、飞行/VoWiFi、通话期间暂缓。目标只在内存中，不写入设备通用选网配置，NAS 请求使用本次开机周期；换卡后恢复设备原选择。
- 私有配置文件热加载，错误/缺失更新保留进程内最后有效白名单。无配置时保留原行为。未修改 MBN/IMS、SIM 禁用网络表、路由或射频策略。

## 测试与实机

- 相关 device/db/backend/vowifihost/API/esim/notify/phone 全包通过，白名单/身份/驻网 race 两轮通过，相关 vet 无诊断。
- 新增回归覆盖已注册电信仍纠正、联通超时移动备用、穷尽白名单不自动回退、稳定备用不反复切网、掉网退避、换卡恢复、实时身份不一致/旧 Worker/射频抑制/锁忙时跳过、配置错误保留和热加载并发。
- 首次全包出现既有 RTP 集成测试异步统计 4/5 的时序问题：UDP 包能先到对端，而本地计数递增稍后才执行。测试改为有界等待统计可见，保留全部精确数量/丢包断言；相关 race 连续十轮通过。额外重复旧 phone 套件还曾出现一次三秒 ICE 建连等待超时；没有跳过该测试，最终常规完整 phone 和后端套件通过。运行媒体代码与 0.1.7 完全一致。
- 前端源码和嵌入产物无变化；本轮未重复宣称重新测试前端或整个 IMS 协议套件。
- 受控入口确认空闲通话后备份、部署，实际版本 0.1.8、程序哈希与构建一致；主 config.yaml 哈希未变。
- 运行后热加载目标卡策略，日志及受保护 API 均确认白色 ec20 已从电信变为中国联通，reg_status=5、healthy/control_online=true；实际底层选网为 manual、PLMN=46001。
- 开机初期模组仍可能在应用/卡身份就绪前自主注册，本功能会在就绪后纠正；未实际断电或重启模组验证。移动备用、两网故障及换卡使用模拟验证，未主动制造真实断网。未主动发短信、Bot 消息或拨号，真实新短信接收/转发待使用验收。

## 恢复

程序 SHA-256：`75b2b8f0a99ac2bd5794f7cf7524e98f2511a317326f9d745a4af9c58200053e`。Release 提供 gzip 安装程序、SHA256SUMS、构建信息和变更清单；完整源码、许可及可构建脚本已同步。新镜像 vohive-plus-personal:0.1.8，原容器挂载保留。

策略位于运行设备主配置同目录 roaming-operators.json，包含卡标识，示例为虚构值。停用时原子替换为 {"version":1,"policies":[]}，等待一个检查周期恢复设备原选择；随后可用齿轮恢复自动。备份含启用配置的私有副本，旧版程序回滚时仅替换程序，不覆盖新短信数据库。
